# Codex 작업 컨텍스트

이 파일은 구현 작업을 시작할 때 먼저 읽어야 할 기준 문서다.

## 작업 목표

연합뉴스 RSS 기반 뉴스 열람 웹 애플리케이션과 개인화 푸시 알림 백엔드 시스템을 하나의 풀스택 프로젝트로 구현한다.

## 디렉터리 경계

- `new-pulse-frontend/`: React/Vite/TypeScript 프론트엔드만 수정
- `new-pulse-backend/`: Spring Boot/SQLite 백엔드만 수정
- `new-pulse-docs/`: 설계, 검증, 배포, 하네스 문서

## 비공개 자료 규칙

- 원본 과제 문서, 원본 사용자 데이터, 제출 안내 원문을 코드나 공개 문서에 복사하지 않는다.
- 문서에는 구현 방식, 실행 방법, 설계 가정, 검증 방법만 적는다.
- 샘플 사용자 데이터는 최종 DB/CSV 검증 산출물에 필요한 범위만 포함한다.

## 구현 원칙

- SQLite와 Spring JDBC 기반으로 단순하고 검증 가능한 구조를 유지한다.
- RSS 수집, 사용자 필터링, 푸시 발송, 이력 저장은 서비스 계층에서 분리한다.
- 시간 처리와 article_id 추출은 작은 순수 함수로 만들고 테스트를 먼저 둔다.
- 프론트엔드는 실제 화면을 첫 진입점으로 둔다. 별도 랜딩 페이지는 만들지 않는다.
- iframe은 외부 사이트 정책으로 막힐 수 있으므로 새 탭 열기를 기본 UX로 한다.
- README는 평가자가 그대로 따라 실행할 수 있는 수준으로 작성한다.
- 사용자 선택이 필요한 설계 결정은 `harness/decision-gates.md`에 선택지와 권장안을 제시한 뒤 결정받는다.
- 기능 구현 후 자동 테스트만으로 끝내지 않고, `harness/test-qa-strategy.md` 기준으로 Chrome 직접 QA까지 수행한다.

## 완료 보고 형식

각 구현 단위가 끝나면 아래를 보고한다.

- 변경 파일
- 구현한 동작
- 실행한 테스트 명령
- 남은 리스크 또는 가정
