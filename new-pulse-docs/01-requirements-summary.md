# 구현 범위와 불변 요구사항

이 문서는 개발 중 변경하지 말아야 할 기능 범위와 구현 가정을 정의한다.

## 구현 범위

두 과제를 하나의 풀스택 프로젝트로 통합해서 구현한다.

1. 뉴스 열람 웹 애플리케이션
   - 카테고리 선택
   - 카테고리별 기사 목록
   - 읽음/미읽음 시각 구분
   - 기사 상세 진입 시 읽음 처리
   - 원문 링크 새 탭 열기 또는 본문 표시

2. 뉴스 기사 푸시 알림 백엔드 시스템
   - RSS 피드 주기 수집
   - 기사 중복 제거와 저장 한도 관리
   - 사용자 선호 카테고리 매칭
   - 사용자별 방해 금지 시간 처리
   - APNS/FCM 인터페이스 호출 시뮬레이션
   - 발송 성공/실패 이력 SQLite 저장

## 샘플 사용자 데이터 분석

제공 Excel은 `users` 시트 1개, 헤더 포함 101행, 사용자 100명으로 구성되어 있다.

- push_type 분포: FCM 70명, APNs 30명
- 선호 카테고리 분포: 정치 57, 북한 61, 경제 63, 산업 63, 사회 56
- 방해 금지 시간 설정: 설정 67명, 미설정 33명
- 방해 금지 시간은 자정을 넘는 구간이 존재하므로 시간대 파서 테스트가 필요하다.

## 설계 가정

- 서버 시간 기준은 `Asia/Seoul`로 고정한다.
- 같은 기사가 여러 RSS 카테고리에 나타날 수 있으므로 기사 본문과 카테고리 매핑을 분리한다.
- 한 사용자에게 같은 기사를 중복 발송하지 않는다.
- 방해 금지 시간에 걸린 사용자는 이번 발송 대상에서 제외한다. 보류 큐는 구현 범위에서 제외하되 README에 가정으로 명시한다.
- 푸시 발송 이력은 실제 발송 시도 결과인 `success` 또는 `fail`만 기록한다.
- 프론트엔드 읽음 상태는 선택지 A로 확정한다. 로그인은 구현하지 않고, 브라우저에서 생성한 익명 `client_id`와 `article_id` 조합으로 백엔드 SQLite에 저장한다.

## 구현 금지 사항

- RSS `guid`를 article id로 사용하지 않는다.
- 사용자별 선호 카테고리 매칭 없이 전체 사용자에게 발송하지 않는다.
- DND 시간대를 프론트엔드에서만 처리하지 않는다. 발송 제외 판단은 백엔드 서비스에서 한다.
- 발송 성공/실패 결과를 로그에만 남기지 않는다. 반드시 SQLite에 저장한다.
- 읽음 상태를 브라우저 localStorage에만 저장하지 않는다. localStorage는 `client_id` 보관에만 사용한다.
- 로그인, JWT, 세션, Redis는 구현하지 않는다. 샘플 사용자 데이터는 푸시 발송 대상자 모델로만 사용한다.
