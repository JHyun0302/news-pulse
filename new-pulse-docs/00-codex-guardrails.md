# Codex 개발 가드레일

## 작업 원칙

- 구현 전에 관련 설계 문서를 먼저 읽고, 문서와 충돌하는 변경은 하지 않는다.
- 한 번에 하나의 기능 단위만 구현한다.
- 변경 범위는 `new-pulse-frontend`, `new-pulse-backend`, `new-pulse-docs` 안으로 제한한다.
- 원본 과제 문서, 원본 사용자 데이터, 제출 안내 원문, 개인정보성 자료를 코드/README/공개 문서에 복사하지 않는다.
- 구현 이유가 필요한 구조 변경은 문서에 먼저 기록한다.

## 코드 품질 기준

- 테스트 없는 핵심 로직은 완료로 보지 않는다.
- 시간, RSS parsing, article id 추출, DND 판단, push dispatch는 단위 테스트를 둔다.
- Controller에 비즈니스 로직을 넣지 않는다.
- 프론트엔드 컴포넌트에 API fetch와 복잡한 데이터 변환을 직접 넣지 않는다.
- magic string은 enum, constant, value object로 이동한다.
- 로그에는 device id 전체값이나 사용자 이름을 남기지 않는다. 필요하면 user_no와 article_id만 남긴다.

## 금지 사항

- 원본 첨부 파일을 이동/삭제/커밋하지 않는다.
- `git reset --hard`, `git checkout --`, 광범위 삭제 명령을 사용하지 않는다.
- 테스트 실패를 README나 주석으로 덮지 않는다.
- 스케줄러만 구현하고 수동 실행 API를 빼지 않는다.
- DB 파일 경로를 코드에 절대경로로 하드코딩하지 않는다.

## 완료 보고 기준

각 작업 완료 시 다음을 확인한다.

- 변경 파일 목록
- 구현 동작
- 실행한 검증 명령
- 남은 리스크
